# Automation

Build, release, maintenance, and operational automation belongs here.

Automation must obtain secrets through the approved runtime secret store, use
least-privilege credentials, avoid printing sensitive inputs, and record the
revision and contract versions used to generate release artifacts.

Before an agent or consequential workflow is enabled, its contract must pin the
governing Constitution version, tag, and commit and identify the responsible
human, authority level, permitted/prohibited actions, data classes, tools,
destinations, budgets, duration, monitoring, revocation, escalation, external
authorization checks, audit evidence, failure tests, rollback, and human
takeover. It cannot self-approve or cross an A4 gate.

Before a release workflow is enabled, it must fix the exact candidate digest,
contents, audience, destination, governing versions, owners, Article 9 gate
results, release notes, notices, migration, monitoring, rollback/withdrawal,
and final A4 publication approval. Published bytes must match the approved
candidate and immutable provenance.
