# ADR 0017: Reusable offline conformance and reviewed reference expectations

- Status: Proposed, accepted by owner merge
- Date: 2026-09-16
- Owner: @andrewperis
- Issue: [Studio #85](https://github.com/DefinitelySecureStudio/studio/issues/85)
- Constitution: 1.0.0 at `a9cc8a503aa30e17820edc62ac95f7cbe10e0564`
- Evidence: [coverage map/suite guide](../context-builder-conformance.md), common adapter/verifier harnesses, pinned reference matrix and CI

Consolidate existing per-boundary tests rather than replace them. Provide common
factory-based source and verifier checks using real adapters with offline backends,
including independent fake implementations. Add explicit full reference expectations
derived from accepted Codex goldens, not generated by the Builder under test.

Pin Platform reference bytes separately, request owner review for expectations and
never rewrite fixtures during test runs. Run a dedicated suite on Node 22/24 with
an accidental-network tripwire and end-to-end Builder/SDK/CLI examples. Preserve
the complete regression run and immutable SDK/contract baseline.

No runtime, dependency, release or Codex contract change is needed. The guard is
not a hostile-code sandbox; conformance is not production service/signature/trust
certification. Repository branch rules govern mandatory code-owner review and are
not changed. Real private/provider integrations require separately approved tests.
Review before golden/contract changes, live backend onboarding or #86 publication.
